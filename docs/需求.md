# 第一款游戏立项需求

## 1. 项目结论

第一款游戏选择：超休闲游戏方向。

具体项目名称：通勤消消乐。

选择理由：

1. 开发周期最短，适合个人开发者尽快完成第一个可上线作品。
2. 核心玩法简单，能把精力集中在完成度而不是复杂系统上。
3. 广告变现路径明确，不需要先搭建复杂付费体系。
4. 失败成本低，适合作为学习完整游戏开发流程的第一项目。

项目目标不是做一款内容庞大的游戏，而是完成一款真正可玩、可测试、可迭代、可上线的小产品。

---

## 2. 项目定位

### 2.1 类型定位

- 类型：2D 超休闲消除游戏
- 平台：移动端优先
- 引擎：Godot
- 操作方式：单指点击或滑动
- 单局时长：30 到 60 秒

### 2.2 用户定位

目标用户：

- 碎片时间游玩的轻度玩家
- 通勤、排队、休息时想快速玩一局的用户
- 不愿学习复杂规则，希望立刻上手的用户

### 2.3 变现定位

- 主要变现：激励广告
- 次要变现：插屏广告

广告触发点：

1. 失败后观看广告复活一次
2. 结算后观看广告获得双倍金币或双倍积分
3. 每日首次奖励可通过广告翻倍

原则：每局广告触发不超过 1 次，避免影响体验。

---

## 3. 核心玩法

### 3.1 一句话描述

玩家在有限时间内快速消除相同颜色的方块，连续消除会触发连击和分数加成，目标是在短时间内打出更高分数。

### 3.2 核心循环

1. 进入关卡
2. 点击或滑动消除相邻同色方块
3. 获得分数与视觉反馈
4. 触发连击与高分奖励
5. 时间结束后结算
6. 选择再来一局或观看广告领取额外奖励

### 3.3 乐趣来源

- 上手快，第一局就能理解规则
- 连击反馈强，容易获得即时满足
- 单局短，失败无压力，愿意重复挑战
- 高分驱动明显，适合反复游玩

## 4. MVP 范围

第一版只做最小可玩版本，不加入复杂系统。

### 4.1 必做功能

- 主菜单
- 游戏主界面
- 基础消除逻辑
- 计分系统
- 倒计时系统
- 连击加分系统
- 游戏结束结算界面
- 重新开始功能
- 音效开关
- 本地最高分记录

### 4.2 暂不加入

- 装备系统

- 在线排行榜
- 社交分享系统
- 多种模式
- 皮肤商城

控制范围的目标是两周内做出完整原型，四周内做出首个可测试版本。

## 5. 玩法规则细化

### 5.1 棋盘规则

- 棋盘大小：6 x 6
- 方块类型：4 种颜色
- 玩家点击两个及以上相邻同色方块时可消除
- 消除后上方方块下落补位
- 空缺由新方块生成补满

### 5.2 分数规则

- 基础消除分：每个方块 10 分
- 一次消除 3 个以上方块时追加奖励
- 连续 3 秒内再次消除视为连击
- 连击倍数逐步提升，但设置上限，避免数值失控

### 5.3 失败与复活

- 时间结束时本局结束
- 每局允许一次广告复活
- 复活后额外获得 10 秒时间

## 10. 成功标准

第一款游戏的成功，不以赚多少钱为唯一标准，而以是否完成完整闭环为标准。

本项目成功标准：

1. 能独立完成从需求到可玩版本的全过程。
2. 至少有 5 名试玩者能在 10 秒内理解玩法。
3. 至少有 3 名试玩者愿意连续玩 3 局以上。
4. 项目具备继续迭代和接入广告变现的基础。

---

## 11. 风险控制

### 主要风险

- 玩法过于普通，缺乏记忆点
- 为了追求完整而不断加功能
- 过早处理广告、登录、排行榜等非核心内容

### 应对方案

1. 先把消除手感做到足够顺畅
2. 每次新增内容前先判断是否影响核心乐趣
3. 原型阶段只保留一个玩法，不做模式扩展

---

## 12. 当前执行结论

如果目标是开发第一款游戏，最合适的方向不是买断制长周期项目，也不是高内容压力的剧情项目，而是：

超休闲方向下的通勤消消乐。

这是当前最适合个人开发者起步的项目，因为它同时满足：

- 范围小
- 开发快
- 容易完成
- 容易测试
- 容易形成第一款上线作品

下一步应直接进入原型开发，而不是继续扩大策划范围。

## 13. 可玩性分析

### 13.1 总体判断

通勤消消乐具备成为合格第一款游戏的可玩性基础。

它的优势不在于玩法创新幅度大，而在于低理解成本、强即时反馈和高重复尝试意愿。这种组合很适合作为超休闲游戏的核心，因为玩家是否愿意继续玩，往往不是看系统深度，而是看第一局是否顺手、第二局是否想刷新分数、第三局是否还能感受到进步。

从个人开发者的角度看，这个项目的可玩性是成立的，但前提是必须把手感、反馈和节奏做好。只要这三点做差，玩法会立刻显得普通。

### 13.2 可玩性的核心来源

#### 一、理解门槛低

消除类玩法的最大优势是用户几乎不需要学习。

玩家看到相同颜色的方块，天然就会尝试点击或连消，这种规则不依赖复杂教学。对第一款产品来说，这很重要，因为新手开发者最容易失败的地方不是技术，而是做出一套用户根本懒得学的规则。

结论：

- 首局上手成本低
- 适合碎片化场景
- 测试反馈来得快

#### 二、即时反馈强

消除、掉落、连击、分数跳字，这些反馈天然适合构成正循环。

只要玩家点击后立刻看到方块消失、分数上涨、连击提示出现，就会产生明显的操作回报感。这种回报感是超休闲游戏里最关键的可玩性来源之一。

结论：

- 每次操作都应有视觉和声音回应
- 玩家会因为反馈爽感继续下一步操作
- 短时间内就能形成基本成瘾循环

#### 三、高分驱动明确

通勤消消乐本质上不是内容消费型游戏，而是分数挑战型游戏。

玩家反复游玩的动机主要来自三个点：

1. 这局差一点就破纪录
2. 刚刚打出了高连击，下一次可能更高
3. 想用更快的判断拿到更高分

这类动机不需要大量内容支撑，只需要一个足够顺畅的循环和可见的成长反馈。

#### 四、单局足够短，失败压力低

30 到 60 秒一局，是这个项目可玩性成立的重要条件。

如果单局太长，玩家会疲劳；如果太短，刚进入状态就结束。超休闲游戏适合让玩家在一次失败后毫无心理负担地再开一局，这也是它适合作为第一款游戏的原因。

结论：

- 适合通勤和碎片时间
- 失败不会造成挫败堆积
- 更容易形成多局重复游玩

### 13.3 当前玩法的可玩性风险

#### 一、基础消除过于常见，容易缺少记忆点

如果只是普通地点一下就消除，玩家会很快把它归类为常见小游戏，玩几局后失去兴趣。

这不是不能做，而是意味着首版必须至少有一个简单但明确的记忆点。

建议记忆点方向：

- 连击时触发明显的节奏加速反馈
- 一次消除多个方块时出现夸张特效和额外奖励
- 引入一个很轻量的特殊块，例如连消达到一定次数后生成爆炸块

注意：只加一个就够，不要同时加复杂规则。

#### 二、决策深度可能不足

如果玩家只需要机械地点任意同色块，就会很快进入无脑操作状态。无脑操作短期爽，长期留存弱。

要提高可玩性，不一定要增加复杂规则，而是要让玩家有一点点判断空间。例如：

- 消除更大的区域能获得更高收益
- 连击窗口较短，促使玩家快速观察与选择
- 某些布局会让玩家考虑先消哪里更划算

核心不是把游戏做复杂，而是让玩家在极短时间内做一个轻决策。

#### 三、随机性可能破坏公平感

消除类游戏高度依赖新方块生成。

如果玩家觉得高分主要靠运气，而不是靠操作判断，就会降低继续游玩的意愿。因此，首版需要控制随机性，不要让棋盘频繁出现无解、无趣或者极端失衡的局面。

建议：

- 控制初始棋盘至少存在多个可消除区域
- 限制随机刷新导致的大面积单色失衡
- 在测试阶段记录玩家平均每局有效操作次数

#### 四、后期疲劳会来得很快

这类游戏的主要问题不是玩家不会玩，而是玩懂后很快腻。

因此它更适合做成强循环、短局、快反馈产品，而不适合靠长时间内容撑住。首版目标不是留住玩家几个月，而是让玩家愿意连续玩几局并留下基本好印象。

这意味着产品成功标准要合理，不能用中重度游戏的标准要求它。

### 13.4 提升可玩性的首版策略

为了保证项目范围不失控，首版建议只做以下四个提升点：

#### 一、把连击做成主要爽点

连击不只是加分，还要体现节奏升级。

建议表现：

- 连击时屏幕文字明显放大
- 音效逐渐增强
- 棋盘边框或背景轻微变化
- 分数跳字更夸张

目标是让玩家清楚感受到自己进入了高状态。

#### 二、增加大消除奖励

当玩家一次消除较多方块时，应获得超出预期的奖励反馈。

例如：

- 5 个以上方块触发额外加分
- 6 个以上方块触发短暂停顿和爆发动画

这样玩家会主动追求更大的消除组合，而不是随便点。

#### 三、加入一个极轻量特殊机制

只推荐加入一种特殊块，作为玩法记忆点。

推荐方案：

- 连续连击 5 次后生成一个爆炸块
- 爆炸块可清除周围一圈方块

这个机制简单、易理解、反馈强，能明显提升爽感，又不会让系统复杂化。

#### 四、结算时强化再来一局冲动

超休闲游戏的关键不只是玩的过程，还包括结算后的再开局冲动。

结算界面建议明确展示：

- 距离最高分还差多少
- 本局最高连击是多少
- 是否打破个人纪录

这样玩家更容易产生再来一局的念头。

### 13.5 可玩性结论

通勤消消乐适合作为第一款游戏，不是因为它天生会爆，而是因为它具备以下成立条件：

1. 玩家易懂，几乎不需要教学。
2. 爽点明确，适合通过反馈强化体验。
3. 单局短，适合多次重复尝试。
4. 开发者可以在较小范围内持续打磨手感。

但必须明确一点：

这款游戏的可玩性上限，不取决于玩法概念本身，而取决于执行质量。

如果执行一般，它会是一款普通小游戏；如果反馈、节奏和连击设计做得好，它会是一款非常合格的第一款产品。

### 13.6 执行建议

开发时优先验证以下三个问题：

1. 玩家是否能在 5 到 10 秒内理解玩法。
2. 玩家是否会因为连击和高分反馈主动再玩一局。
3. 玩家是否会在 3 局之后仍然觉得操作有意思，而不是重复点击。

如果这三个问题成立，通勤消消乐的可玩性就已经达到第一款游戏应有的标准。

#### Day 2：棋盘生成 + 方块预制（1.5小时）

**核心需求**：

- 棋盘大小：7×7
- 方块类型：4种颜色（用代码颜色值即可：红/黄/蓝/绿）
- 随机填充：每个格子随机选择一种颜色
- 方块大小：80×80 像素，间距 2 像素

**Block.gd 实现**：

```gdscript
extends Area2D

@export var col: int = 0  # x坐标在棋盘中的列号
@export var row: int = 0  # y坐标在棋盘中的行号
@export var color_id: int = 0  # 0=红, 1=黄, 2=蓝, 3=绿

var colors = [Color.RED, Color.YELLOW, Color.BLUE, Color.GREEN]

func _ready():
	var rect = ColorRect.new()
	rect.color = colors[color_id]
	rect.size = Vector2(80, 80)
	add_child(rect)

	# 触摸反馈
	area_entered.connect(_on_area_entered)

func set_position_in_grid(col: int, row: int):
	self.col = col
	self.row = row
	position = Vector2(col * 82, row * 82)  # 82 = 80 + 2间距
```

**Grid.gd 初步实现**：

```gdscript
extends Node2D

const GRID_SIZE = 7
const BLOCK_SCENE = preload("res://Scenes/Block.tscn")

var grid = {}  # 字典：Vector2i(col, row) -> Block节点

func _ready():
	generate_grid()

func generate_grid():
	for row in range(GRID_SIZE):
		for col in range(GRID_SIZE):
			var block = BLOCK_SCENE.instantiate()
			block.color_id = randi() % 4
			block.set_position_in_grid(col, row)
```

#### Day 3：核心消除逻辑 + 下落补位（3小时）

**这是最关键一天，掌握整个消除流程。**

**消除流程**：

1. 玩家触摸方块 → 调用find_connected()查找相邻同色方块
2. 如果≥3个，消除它们 → 上方方块下落 → 新方块补位
3. 反复检测，直到无法再消除

**Grid.gd 完整消除逻辑**：

```gdscript
# 查找相连的同色方块（BFS广度优先搜索）
func find_connected(col: int, row: int) -> Array:
	if not grid.has(Vector2i(col, row)):
		return []

	var target_color = grid[Vector2i(col, row)].color_id
	var visited = {}
	var queue = [Vector2i(col, row)]
	var result = []

	while queue.size() > 0:
		var pos = queue.pop_front()
		if pos in visited:
			continue
		visited[pos] = true
		result.append(pos)
	
		# 检查4个方向的邻居
		for neighbor in [Vector2i.UP, Vector2i.DOWN, Vector2i.LEFT, Vector2i.RIGHT]:
			var new_pos = pos + neighbor
			if grid.has(new_pos) and not new_pos in visited:
				if grid[new_pos].color_id == target_color:
					queue.append(new_pos)

	return result if result.size() >= 3 else []

# 触摸处理
func _input(event):
	if event is InputEventMouseButton and event.pressed:
		for block_pos in grid:
			if grid[block_pos].get_node("Area2D").get_global_rect().has_point(event.position):
				on_block_clicked(block_pos)

func on_block_clicked(pos: Vector2i):
	var to_remove = find_connected(pos.x, pos.y)
	if to_remove.size() >= 3:
		remove_blocks(to_remove)
		fall_blocks()
		refill_grid()

# 消除方块
func remove_blocks(positions: Array):
	for pos in positions:
		grid[pos].queue_free()
		grid.erase(pos)

# 上方方块下落
func fall_blocks():
	for col in range(GRID_SIZE):
		var write_row = GRID_SIZE - 1
		for read_row in range(GRID_SIZE - 1, -1, -1):
			var pos = Vector2i(col, read_row)
			if grid.has(pos):
				var block = grid[pos]
				var new_pos = Vector2i(col, write_row)
				if new_pos != pos:
					grid.erase(pos)
					grid[new_pos] = block
					block.set_position_in_grid(col, write_row)
				write_row -= 1

# 补新方块
func refill_grid():
	for col in range(GRID_SIZE):
		for row in range(GRID_SIZE):
			var pos = Vector2i(col, row)
			if not grid.has(pos):
				var block = BLOCK_SCENE.instantiate()
				block.color_id = randi() % 4
				block.set_position_in_grid(col, row)
				add_child(block)
				grid[pos] = block
```

### 14.6 避坑清单（最常见失败原因）

1. ❌ **过度设计**：不要在首周加入"皮肤系统""关卡编辑器""在线排行榜"

   - ✅ 只做最小循环，迭代再加
2. ❌ **美术太复杂**：不要用高保真像素画、2.5D建模

   - ✅ 纯色块 + 几何图形足够
3. ❌ **广告太频繁**：每局超过1次广告，用户直接卸载

   - ✅ 步数用尽+结算 = 最多2个触发点
4. ❌ **版本控制不做**：代码没备份，改错了找不回

   - ✅ 用 Git，每天commit一次（GitHub/Gitee 免费）
5. ❌ **测试靠推理**：想象假设游戏怎样，不实际跑

   - ✅ 每天给2个人试玩5分钟，记录卡点
6. ❌ **纠结细节**：花3天调整一个颜色，忽视核心玩法

   - ✅ 功能优先 > 美术调整，能玩 > 好看
